# Continuous research operating agreement

## Objective and authority

Develop MatterLab into an English-only open-source virtual materials R&D platform, and advance generated composition/structure hypotheses toward reproducible, application-relevant computational evidence. The owner authorized unattended continuation, GPT Astra roles, and public English GitHub publication on 2026-10-24. This authorizes ordinary reversible implementation, local computation, testing, documentation, and publication of reviewed project files. It does not authorize spending, physical synthesis, account/security changes, outreach, or unsupported scientific claims.

All interfaces, generated reports, model/candidate cards, documentation, code comments, commit/PR/release text, and public artifacts must be English. Private historical evidence can remain in its original language and must not be silently altered. Public releases must pass the publication audit; never push the private workspace history, account metadata, local home paths, credentials, old Chinese screenshots, or installation caches.

## Each scheduled continuation

1. Read this agreement, AGENTS.md, and project/STATE.json. Inspect Git status and active jobs. Preserve unrelated work; do not launch overlapping simulations or duplicate a running campaign.
2. Check current Codex included usage through the account usage tool before substantial model work and before delegation. If the check is unavailable, ordinary included use is disallowed, or a reported window is at least 80% consumed, do not start heavy model work. Save a checkpoint and defer until included allowance is available. These are shared-account snapshots, not a project bill or a billing enforcement mechanism.
3. Use GPT Astra (gpt-6-astra) for delegated scientific, implementation, or review roles when useful. Do not downgrade models or create paid API clients. Prefer a single coherent task per continuation, with independent roles only when they add clear value. Local saved simulations do not need GPT calls.
4. Select the highest-priority unresolved scientific or engineering question. Record the hypothesis, cheapest decisive check, acceptance criterion, and stopping condition before running it. Complete a useful verified increment, not another copy of the same failed attempt.
5. Keep new runs in new directories with seeds, settings, code/model/environment hashes, raw observations, uncertainties, and failures. Never change an acceptance threshold just to pass. If criteria need scientifically justified revision, retain and report the original result and the reason for the new protocol.
6. Update project/STATE.json with what changed, evidence paths, current blockers, active job identifiers, and the next exact action. Publish only reviewed English release content using the publication export/audit workflow. Do not push the workspace repository or force-push public history.
7. Notify only on a substantive milestone, completion, a new failure that changes the plan, or a decision/access requirement. Do not repeatedly notify about unchanged quota/resource blocks or routine status.

## Zero-spend boundary

Use only existing signed-in Codex Pro allowance, subscription-included native cloud execution, and free software/data. The owner requested cloud continuation on 2026-10-24; follow project/CLOUD_MIGRATION.md and its verification gates. Free local computation remains a fallback until a cloud handoff is verified. No model API charges, prepaid credits, quota-reset purchases, paid overage, cloud rental, paid databases, subscriptions, or paid GitHub features. Do not route subscription credentials into an API or copy credentials into project files. Do not change host sleep/security settings without a separate user request. Local scheduled work requires the machine and desktop app to remain available.

When resources are unavailable, checkpoint and resume later. Do not promise that a sleeping/offline machine will keep computing, that Pro is unlimited, or that research success is guaranteed.

## Acceptance and milestones

- **P1: public engineering release.** English-only MIT source, usable local UI/CLI, documented installation and replay, actual first-round evidence, application hypotheses and limitations, a public GitHub repository, and an audited release. This is a platform milestone, not a material discovery.
- **S1: resolve the current numerical uncertainty.** Diagnose Gamma finite-difference asymmetry/translation residuals on C03-005 and a known reference using controlled displacement sizes and an independent derivative or graph-continuity check. Preserve an inconclusive outcome when residuals prevent interpretation. Do not claim full phonon stability from a Gamma-only result.
- **S2: independent physics.** Select a small justified candidate/reference set, converge DFT settings for the quantities used, compare multiple structural starts and relevant competing phases, and identify the model's applicability limits. The previous fixed cubic CaTiO3 runs establish solver execution only; their cutoff check failed and they do not validate candidates.
- **S3: application evidence.** Choose a concrete target such as dielectric ceramics for capacitors/electronic packaging. Declare the baseline, computed property, evaluation conditions, uncertainty, and acceptance criterion before computation. Compute relevant properties rather than substituting density or compression response for dielectric/thermal/strength performance.
- **Research handoff.** Deliver a small candidate dossier with bounded novelty searches, independent reproducibility, appropriately converged physics, explicit competing-phase coverage, application-specific evidence and remaining experimental work. This is a virtual R&D result, not experimental synthesis or product certification.

Code publication alone does not complete the research objective. A failed search is useful evidence but not a discovery. If this material family is rejected, another scientifically justified free/local search is within scope; record the decision. If continued progress requires unavailable resources or a material change to the objective, report the concrete blocker and the smallest decision needed instead of repeating low-information runs.

Once the documented overall acceptance is met, deliver a final report and stop the recurring automation. Do not mark completion merely because quota is low, and do not continue polishing after acceptance is satisfied.
